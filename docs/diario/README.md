# Diario di lavoro

Qui resta la traccia di **come** è stato svolto ogni piano di implementazione, non solo del risultato (quello sta in `CHANGELOG.md` e nel codice).

Un file per piano completato, chiamato `AAAA-MM-GG-<nome>.md` (la data è quella di chiusura del piano). Ogni file contiene:

- i **task** con i loro commit e le PR;
- i **giri di revisione** (cosa è stato trovato, cosa è stato corretto);
- le **decisioni prese in autonomia**, nella forma *Decisione: cosa — perché — costo se sbagliata*;
- i **problemi rinviati**, con il sotto-progetto o la PR dove sono stati ripresi;
- le **verifiche finali**.

Il diario nasce dal registro che l'agente tiene durante il piano in `.superpowers/sdd/<piano>/progress.md`. Quella cartella è ignorata da git e viene cancellata a fine piano: per questo, **prima** di cancellarla, il registro si riscrive qui (regola in `CLAUDE.md`).

I collegamenti a specifiche e piani sono link relativi Markdown, validi sia in Obsidian sia su GitHub.
